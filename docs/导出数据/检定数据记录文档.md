## 2. 码值转换后仍不能用的阻断项（必须提出）

### A.【硬阻断·算法硬编码】`MAX_WORK_DATE = 2026-04-30` 与 0812 排程时间冲突 → 整个排程为空

- 8.11 L314：`MAX_WORK_DATE = datetime(2026,4,30).date()`，注释写「排程时间配置中最后一天」，**实现却是写死的**。
- 0812 `scheduleTimeList` 工作日为 **2026-08-12 ~ 08-31**（20 天），全部 `> 2026-04-30` → `is_workday()` 恒 False → **排不出任何任务**。
- **【已解决 2026-08-16】** 已改为动态计算：`prepare.process_data()` 取 `time_config`（scheduleTimeList）的最大工作日日期覆盖 `scheduler.MAX_WORK_DATE`，默认值 `date.max`（不设上限）。0812 现推导为 `2026-08-31`，可排出 18 行/71 台。核心 `is_workday` 函数未改。

### B.【硬阻断·数据语义】`detectSchList.schTime ∈ {0,1,10}` 被当作「自动检定时间」（检定时长）

- 8.11 把 `spec.自动检定时间` 作为调度时长 `spec_time[分类]`；0812 中该列取自 `schTime`，值为 **0 / 1 / 10**，与默认检定时长（三相 414 / 单相 108 / 互感器 25 分钟）量纲完全不符。
- **实测杀伤**：设备码 `test_dev0610001`（低压电流互感器，需求 4+2、到货 2 批）同时出现在需求/到货/检定方案三处，`schTime='1'` → `spec_time['低压电流互感器'] = 1`（覆盖默认 25）→ 低压CT 批次按 **1 分钟/批** 排。
- 另 27 个 schTime 设备码不在需求/到货中、无分类，暂不参与排程（多为测试假码，如 `'互感器'`/`'wqeq123'`/`'12312'`）。
- 码值转换解决不了。**需算法负责人确认 schTime 口径**（检定方案序号？时长？单位？），否则排程时长错误。

### C.【映射口径不一致】VW_DETECT_EQUIP_TYPE 4 个编码转出的名称，算法分类器认不出 → 24 行仓被丢弃

| 编码 | 转换后名称 | 算法 `parse_device_category` 关键词 | 命中 |
|---|---|---|---|
| 12/16 | 负荷**管理**终端 | 只认「负荷**控制**终端」 | ✗ |
| 13/17 | 配变监测**计量**终端 | 只认「配变监测终端」 | ✗ |

- 0812 实测：`deviceParaList` 中这 4 个编码共 **24 行**仓（12/13/16/17 各 7/7/5/5 行），转换后分类为 None → `chambers` 里被**静默跳过**。
- 两个口径还不一致：`reader._infer_category` 补了「负荷管理终端」但没补「配变监测计量终端」。
- 需算法负责人**改分类关键词**（加「负荷管理终端」「配变监测计量终端」）或统一名称口径。

### D.【数据缺失】`arriveBatchList.detectEquipType` 0812 全空（16/16）→ 接入方式推断失效

- 接口无「接入方式」字段，只能从 `detectEquipType` 编码 11-14（经互感）/ 15-18（直接）推断；0812 该字段**全空** → 接入方式全空。
- 影响：`智能量测终端` + 仓类型 5（终端仓）需接入方式含「经互感」才可用；0812 到货含 `equipCls='19'`（智能量测终端）2 批 → 无接入方式 → **这 2 批排不出来**。
- 需接口方补充该字段，或算法负责人确认终端仓过滤口径。

### E.【字段缺失·可兜底】`dmdPlanDetList` 无 `detectEquipType` 字段

- 需求设备码分类只能靠 `equipCls` 转换兜底。0812 恰好 `equipCls` 可转出（单相/低压CT），能兜住；但若 `equipCls` 缺值或为未定义编码，需求分类即缺失。需确认需求分类来源。

### F.【列缺失】spec 缺「设备码描述」→ 低压互感器子类型（大变比/DBI）无法区分

- 8.11 用 `设备码描述` 关键字区分 低压电流互感器 → 大变比/DBI/普通；0812 的 `equipDesc` 在到货/需求集合里有值，可作来源，但当前合成 spec 未带该列 → 子类型全按普通型。需算法负责人确认描述来源。
